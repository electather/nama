# Plugin system

The first Jellyfin integration is a separate first-party TypeScript executable bundled in the application image, launched and supervised by the core, and called through `nama.plugin.v1` ConnectRPC over an HTTP/1.1 Unix domain socket ([ADR-0006](../adr/0006-stateless-supervised-plugin-subprocesses.md)). The core owns configuration, credentials, timeouts, restarts, logging, schedules, cursors, retries, and all durable state. Plugins translate provider APIs into Nama messages; they receive no database, queue, migration system, marketplace, installer, WASM host, or stable third-party SDK in the MVP.

The implemented `PluginSupervisor` is an Effect-scoped core service. It creates a mode-`0700` runtime root and per-launch directory, validates a fixed absolute non-symlink executable owned by root or the runtime user, launches a detached process group with an empty environment, and sends one bounded versioned JSON envelope containing a fresh 32-byte base64url bearer and Unix-socket path through stdin before EOF.

A process is ready only after its socket is mode `0600`, the authenticated health check succeeds, `PluginService.GetInfo` returns the expected provider type, and contract major `1` is confirmed. The service shares concurrent acquisition and recovery attempts, requires explicit per-call deadlines, retains a healthy process on ordinary cancellation, recycles a process that exceeds a deadline, never replays an interrupted RPC, bounds recovery to three launches with 100/500 millisecond backoff, and resets recovery after 60 seconds of healthy service.

Child stdout is drained and discarded. Stderr is newline-delimited JSON bounded to 4 KiB, admitted only through code-owned event and field declarations, and rate-limited to 20 records per second with a burst of 40. Lifecycle and accepted child records use the existing structured logger's allowlisted provider fields; rejected content is never reflected. Plugin failures remain local unavailable outcomes and never manufacture `server.runtime_failed`.

The supervisor participates in the root Effect scope. Shutdown stops accepting new plugin work after the public-request drain, terminates all supervised process groups with `SIGTERM` and a two-second escalation to `SIGKILL`, reaps direct children, removes launch artifacts, and removes the runtime root. Provider-instance persistence, on-demand acquisition policy, provider connectivity, Jellyfin behavior, resource limits, and container packaging remain deferred to their owning milestones.
