# Persist watch state as versioned relational snapshots

Nama persists sparse canonical Watch state and normalized Provider replicas as separate relational snapshots rather than an append-only event ledger or JSON aggregate. Canonical state is keyed by authenticated user and playable canonical item; each replica is keyed by that user and one exact provider item mapping. The canonical snapshot keeps watched status, optional position and duration, the last known playback Source, selected activity evidence, a distinct Activity origin, database commit time, and a core-owned monotonic version; replicas separately keep the normalized provider observation, opaque provider revision, and their own core-owned monotonic version.

Persistence accepts only fully resolved canonical targets and atomically compare-and-commits them with replica replacements against expected versions. Exact canonical value equality changes neither selected activity evidence, commit time, nor version, while a stale expectation returns current snapshots so the owning policy can recompute rather than replaying an obsolete target. Provider-instance deletion removes its replicas and live references but preserves decoupled canonical state; this accepts bounded current-state evidence and caller recomputation instead of unbounded history or persistence-owned reconciliation policy, leaving playback ingestion, public projections, scheduling, precedence, exports, fingerprints, retries, and polling to their owning milestones.
