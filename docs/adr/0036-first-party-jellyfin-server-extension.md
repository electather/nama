# Require a first-party Jellyfin server extension

Stock Jellyfin 10.11.11 cannot issue an expiring item- or session-scoped media credential, expose every playback decision required by Nama, or apply the complete coherent progress target through its public API without either leaking broad authorization or splitting one logical write. Nama therefore requires a manually installed first-party Jellyfin server extension for Jellyfin playback and coherent progress export. An absent, unhealthy, or incompatible extension advertises none of those capabilities; the implemented stock provider profile remains available.

The extension is an exact-versioned .NET 9 artifact owned under `extensions/jellyfin/`, distinct from the supervised TypeScript provider plugin under `plugins/jellyfin/`. It exposes a bounded private JSON/HTTP protocol authenticated by the provider instance's configured Jellyfin API key. Nama negotiates only that protocol and its capabilities; the extension validates its own Jellyfin host and fails closed. The extension owns a purpose-separated ASP.NET Data Protection key ring persisted under stable Jellyfin program data and treated as secret backup material.

Public playback locators contain an opaque extension URL and one scoped request header. The extension validates a self-contained lease before internally dispatching to Jellyfin, and rewrites bounded playlists and subtitle documents so every main, child, key, and subtitle URL stays in its namespace. Plans expire after five minutes. Session leases expire after the complete expected runtime plus 30 minutes, capped at 24 hours. The scoped-access guarantee covers only access conferred by Nama: Nama never reveals stock Jellyfin paths, provider identifiers, or reusable credentials, while independently discovered stock Jellyfin routes retain their existing behavior.

Playback telemetry is the only Jellyfin writer for playback-originated state. Coherent progress export handles other activity origins by atomically saving watched state and position, validating optional duration against current item runtime, and reading the result back. Jellyfin supplies no revision, compare-and-swap, or provider idempotency key, so lost or conflicting outcomes remain ambiguous rather than being blindly replayed.

This adds a version-coupled artifact, manual installation, protected key management, and exact provider fixtures, but avoids a Nama media relay, a maintained Jellyfin fork, automatic remote code installation, extension-owned user-state storage, and a permanent broad-credential exception.
