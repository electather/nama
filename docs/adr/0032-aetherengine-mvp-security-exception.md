# Use AetherEngine 6.21.0 with a bounded MVP security exception

Nama will pin AetherEngine `6.21.0` and its complete resolved dependency closure behind the single `NamaPlayer` adapter. The private single-user MVP accepts that the engine may write complete short-lived locator URLs to its local Release logs and may forward locator headers when a request moves to another core-validated `allowed_redirect_origins` origin; accepting these known limitations delivers the already exercised engine without delaying the MVP for another engine search.

This decision supersedes only ADR-0013's no-locator-logging and exact-origin header-stripping requirements for the selected Apple engine during the MVP. The core still rejects reusable Administrator, Device, and provider-account credentials; clients still reject destinations outside the validated redirect allowlist; Nama-owned code does not persist, upload, log, or expose locator material; and user-facing failures remain secret-free. Post-MVP [issue #158](https://github.com/electather/nama/issues/158) removes both exceptions before the direct locator boundary is described as fully origin- and log-safe.

AetherEngine remains confined to the concrete adapter. Nama records the exact source revision, resolved dependency versions and checksums, LGPL-3 Apple Store/DRM exception, corresponding source, linkage, notices, and relinking obligations before distribution.
